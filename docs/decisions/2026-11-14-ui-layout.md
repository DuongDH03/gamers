# UI layer: layout A, a WebView2 window draws everything

- Date: 2026-11-14
- Status: **Accepted** (owner, 2026-11-14).
- Spec: `docs/specs/2026-11-14-offline-essentials-and-ui.md`, Part 6.

## Problem

The owner wants menus and HUD written in React/HTML/JS, while shipping a
native exe (Tauri/Electron style, not a browser build). Two layouts were open
since 2026-11-12 (`docs/plan.md`).

## Options

- **A. A WebView2 window draws everything.** A new `webview2` backend: a Win32
  window with a WebView2 control implements `Window`, `Input` and
  `Renderer2D`. The Views' triangle batches and textures go to WebGL2 through
  shared memory; React runs in the same page. The native engine (simulate,
  server, net, audio) is unchanged.
- **B. The engine draws the world; HTML is an overlay.** Keep `sdl3` and render
  React offscreen with Ultralight (closed, about 40 MB) or CEF (open, about
  150 MB, multi-process), composited as a texture.

## Decision

**A.** `Renderer2D` is only textures plus triangle batches, so a WebGL backend
is small and every View is reused unchanged. The WebView2 runtime is part of
Windows 11, the SDK is MIT, and React gets Edge DevTools on the real game UI.

## Consequences

- The React UI build is Windows only. The `sdl3` build stays as it is,
  cross-platform, with the debug HUD.
- About one more frame of display latency through the browser compositor.
- Node is needed to build the UI (`ui/`, Vite + React + TypeScript).
- UI game actions are `Command`s (Rule 1). App actions (save, load, pause, quit)
  call the app. The backend is a new backend (Rule 3).
